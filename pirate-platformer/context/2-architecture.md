# Architecture Context

## Stack

| Layer          | Technology                          | Role                                                                 |
| -------------- | ----------------------------------- | -------------------------------------------------------------------- |
| Build          | Vite 7 (vanilla template)           | Dev server, ES module bundling, static asset serving, production build |
| Language       | JavaScript (ES2022 modules)         | All application code. No transpiled superset.                          |
| Types          | JSDoc + `jsconfig.json` `checkJs`   | Editor-level type checking with zero build cost                        |
| Rendering      | Canvas 2D                           | The game world only — tiles, entities, parallax                        |
| UI             | DOM + CSS, `border-image` nine-slice | Every screen, panel, palette, HUD and on-screen control                |
| Audio          | Web Audio API                       | Decoded buffers, one `AudioContext`, unlocked on first input           |
| Storage        | `localStorage`                      | Levels, campaign progress, settings                                    |
| Asset build    | `sharp` (devDependency)             | Packs 1204 loose frame PNGs into per-clip strips and UI nine-slices    |
| Tests          | `vitest` (devDependency)            | Pure modules: codec, autotiler, collision resolver, schema validation  |
| Offline        | Vite PWA manifest + service worker  | Installable, playable offline after first load                         |

No game engine, no physics library, no UI framework. Every dependency above is either
build-time or a browser API.

## System Boundaries

```
coral-corsairs/
├── CLAUDE.md                  entry point, read first every session
├── index.html                 single page, canvas + #ui root
├── jsconfig.json              checkJs
├── vite.config.js
├── context/                   this context system, plus specs/
├── reference/                 READ-ONLY source material, gitignored
│   ├── treasure-hunters/      the Pixelfrog art pack
│   ├── pirate-maker/          Clear Code's editor project (Python)
│   └── super-pirate-world/    Clear Code's platformer project (Python) + CC0 audio
├── tools/                     build-time Node scripts (never imported by src/)
├── public/assets/             GENERATED by npm run assets — never hand-edit
└── src/
    ├── main.js
    ├── settings.js
    ├── core/
    ├── level/
    ├── data/
    ├── game/
    ├── maker/
    ├── ui/
    └── storage/
```

- `src/core/` — the engine. Fixed-timestep loop, viewport and scaling, camera,
  pointer/keyboard input, atlas loading, sprite and animation playback, audio, rect
  math. **Knows nothing about pirates, levels, enemies or the maker.** Nothing in
  `core/` may import from `game/`, `maker/`, `level/`, `data/` or `ui/`.
- `src/level/` — everything both modes share about a level. `model.js` (mutable
  in-memory level), `codec.js` (serialise, parse, share codes), `autotile.js`
  (neighbour bitmask to sheet cell), `schema.js` (defaults and validation),
  `render.js` (tile layers and parallax drawing). Imported by both `game/` and
  `maker/`; imports neither.
- `src/data/` — declarative data with no behaviour beyond factory references.
  `palette.js` (the entity registry), `themes.js` (tilesheet per theme),
  `tuning.js` (physics and gameplay numbers), `atlas.json` (generated),
  `campaign/*.json` (levels exported from our own maker).
- `src/game/` — play mode. Scene, world, physics resolution, player, entities,
  hazards, collectibles, HUD data. Owns nothing the maker needs.
- `src/maker/` — maker mode. Scene, edit commands and the undo stack, tools,
  validation, grid overlay. Owns nothing play mode needs.
- `src/ui/` — every DOM screen and component, plus CSS. The only place that
  touches `document` outside of `core/input.js` and `core/viewport.js`.
- `src/storage/` — the only place that touches `localStorage`. Wraps every access
  in try/catch and falls back to an in-memory map.
- `tools/` — Node scripts run by npm scripts. Reads the read-only reference art,
  writes `public/assets/` and `src/data/atlas.json`. Never imported by `src/`.

### Read-only reference sources

Everything under `reference/` is source material. **Never edit it**, and never import
from it at runtime — only `tools/` reads it, at build time. It is gitignored: with
`public/assets/` committed, the game clones, builds and runs without the pack, and
only `npm run assets` needs it restored.

| Need                                                | Reference                                             |
| --------------------------------------------------- | ----------------------------------------------------- |
| Player physics, semi-solid platforms, wall jump, camera bounds | `reference/super-pirate-world/code_complete/player.py`, `groups.py` |
| Entity registry, editor canvas model, transition wipe          | `reference/pirate-maker/28_finish/settings.py`, `editor.py`, `main.py` |
| All sprites                                                    | `reference/treasure-hunters/**/Sprites/`              |
| All audio (CC0)                                                | `reference/super-pirate-world/audio/`                 |

## Rendering Model

- **World unit = one art pixel. `TILE = 32`.** The Treasure Hunters art is authored
  at 32 px per tile; Clear Code upscaled it 2× for their 64 px projects. We render at
  native scale and upscale the whole canvas instead.
- **Virtual viewport is 360 units tall, always** — 11.25 tiles, the same field of
  view Super Pirate World showed at 720/64.
- **Virtual viewport width = `clamp(round(360 × displayAspect), 512, 768)`.** The
  view widens on wide phones and narrows on 4:3 tablets. Nothing is letterboxed,
  which matters because the maker needs every pixel on a small screen.
- Canvas backing store is `virtualSize × pixelScale`, where `pixelScale` is capped
  at 2 for memory. `ctx.imageSmoothingEnabled = false`.
- All draw destinations are rounded to whole world pixels before `drawImage`.
- Draw order is by `z` from `settings.js`:
  `bg(0) · clouds(1) · bgTiles(2) · bgDecor(3) · main(5) · water(6) · fg(7) · fx(8)`.
- Only tiles intersecting the camera rect are drawn — iterate the visible cell
  range, never the whole grid.

## Level Schema (format 1)

One schema serves both modes. Campaign levels are maker exports.

```json
{
  "format": 1,
  "id": "lvl_7k3n8q",
  "name": "Cannon Cove",
  "author": "",
  "theme": "island",
  "cols": 160,
  "rows": 24,
  "created": 1757030400000,
  "modified": 1757030400000,
  "spawn": { "c": 4, "r": 18 },
  "goal":  { "c": 152, "r": 16 },
  "layers": {
    "terrain":  "0:412,1:18,0:3,1:9,0:3398",
    "platform": "0:3840",
    "water":    "0:3600,1:240"
  },
  "decor":    [ { "k": "palm_back", "c": 12, "r": 14 } ],
  "entities": [ { "k": "crabby", "c": 30, "r": 17, "p": { "dir": -1 } } ]
}
```

**Rules**

- `format` is checked on load. Unknown versions are rejected with a readable error,
  never silently coerced.
- Kind ids (`k`) are **strings**, not indexes, so reordering `palette.js` can never
  corrupt saved levels.
- Tile layers are run-length encoded as `"<value>:<count>"` joined by `,`.
  Cell values are `Uint8`: `0` = empty, `1` = present. `2`–`255` are reserved for
  future variants. Run counts must sum to exactly `cols × rows` — this is a
  validation error, not a warning.
- Every entity and decor sits in exactly one cell. There are no pixel offsets.
- `spawn` is required and singular. `goal` is required. Both are markers, not
  entities, so they can never be duplicated or deleted by a paint stroke.
- Limits: `cols` 40–400, `rows` 12–48, ≤ 400 entities, ≤ 2000 decor. Defaults are
  160 × 24.

**In memory**, `LevelModel` holds one `Uint8Array(cols * rows)` per tile layer plus
plain arrays for entities and decor. `codec.js` is the only module that converts
between the model and the serialised form.

## Autotiling

Terrain and platform tiles pick their sprite from a 4-neighbour bitmask over the
**same layer**: `N = 1, E = 2, S = 4, W = 8`, bit set when that neighbour is present.
Cells outside the grid count as absent.

`Terrain (32x32).png` is a 17 × 5 grid of 32 px tiles containing 47 blob-set tiles.
Sixteen of them form a complete 4-neighbour set, verified against the sheet:

| mask | tile (col,row) | meaning        | mask | tile (col,row) | meaning       |
| ---- | -------------- | -------------- | ---- | -------------- | ------------- |
| 0    | (4,4)          | single         | 8    | (2,4)          | bar right cap |
| 1    | (4,2)          | column bottom  | 9    | (2,2)          | bottom-right  |
| 2    | (0,4)          | bar left cap   | 10   | (1,4)          | bar middle    |
| 3    | (0,2)          | bottom-left    | 11   | (1,2)          | bottom edge   |
| 4    | (4,0)          | column top     | 12   | (2,0)          | top-right     |
| 5    | (4,1)          | column middle  | 13   | (2,1)          | right edge    |
| 6    | (0,0)          | top-left       | 14   | (1,0)          | top edge      |
| 7    | (0,1)          | left edge      | 15   | (1,1)          | fill          |

All sixteen masks are covered and every tile is used exactly once. The table is also
derivable in closed form, which is what `autotile.js` should implement — the table
above is the specification the tests assert against:

```js
const col = (e && w) ? 1 : e ? 0 : w ? 2 : 4;
const row = (n && s) ? 1 : s ? 0 : n ? 2 : 4;
```

The Pirate Ship sheet (`Terrain and Back Wall (32x32).png`, 608 × 416) contains the
**identical layout twice**, padded by one tile. The same table applies with a per-theme
tile origin offset — `(0,0)` for island, `(1,1)` for ship. Themes therefore change one
number and one image path; the tiling logic never changes.

The remaining 31 tiles are inner-corner variants. They are deliberately unused in v1
and are the subject of a later polish unit.

## Physics Model

Ported from `reference/super-pirate-world/code_complete/player.py`, **not** from
PirateMaker (whose gravity is frame-rate dependent and whose
`self.rect.y += self.direction.y` line is dead code overwritten by `move()`).

- **Fixed timestep of 1/60 s** driven by an accumulator, capped at 5 substeps per
  frame to prevent a spiral of death after a tab regains focus.
- Float AABBs. Each entity keeps an `oldRect` snapshot taken at the top of its
  update; collisions are resolved by comparing old and new edges. This is what makes
  one-way platforms, drop-through and moving-platform carry correct rather than
  approximate.
- Horizontal then vertical resolution, in that order, against solid tiles.
- Semi-solid platforms collide only when the player's `oldRect.bottom` was above the
  platform top and vertical velocity is downward. A drop-through timer suppresses
  them while Down is held.
- Wall slide when airborne and touching a wall; wall jump pushes away from it and
  locks horizontal input for a short window.
- Terminal fall speed is clamped so nothing tunnels through a one-tile floor.
- Coyote time and jump buffering are added; neither Python reference has them.

Starting values live in `src/data/tuning.js`, derived by halving Super Pirate World's
numbers because our art is half-scale:

| Constant        | Value    | Constant       | Value  |
| --------------- | -------- | -------------- | ------ |
| `runSpeed`      | 100 px/s | `coyoteTime`   | 90 ms  |
| `gravity`       | 650 px/s² | `jumpBuffer`   | 120 ms |
| `jumpVelocity`  | 450 px/s | `stompBounce`  | 300 px/s |
| `maxFallSpeed`  | 400 px/s | `wallSlideGravity` | gravity / 10 |
| `hitInvuln`     | 700 ms   | `dropThrough`  | 150 ms |

Player collision box is **18 × 26**, with the sprite drawn at
`(hitbox.x - 23, hitbox.y - 6)` — measured from the 64 × 40 idle frame, whose opaque
art occupies x 20–44, y 4–32. Every entity declares its own hitbox and draw offset
the same way, measured from its idle frame, never guessed.

## Entity Registry

`src/data/palette.js` is the single source of truth for everything placeable. It is
the direct descendant of `reference/pirate-maker/28_finish/settings.py:8` (`EDITOR_DATA`).

```js
{
  id: 'crabby',              // stable string, written into level files
  group: 'enemies',          // maker palette tab
  label: 'Crabby',
  icon: 'crabby/idle',       // atlas clip for the palette button and preview
  placement: 'entity',       // 'tile' | 'entity' | 'decor' | 'marker'
  layer: null,               // tile layer name when placement is 'tile'
  z: Z.main,
  spawn: (world, cell) => new Crabby(world, cell),
}
```

The maker palette, the maker preview, the play-mode spawner and the level validator
all read this one array. **Adding an enemy is one entry plus one class.**

## Storage Model

All keys namespaced `cc:v1:`. Every read and write goes through
`src/storage/safe-storage.js`, which try/catches and falls back to an in-memory map
so private browsing degrades instead of throwing.

| Key                  | Contents                                                              |
| -------------------- | --------------------------------------------------------------------- |
| `cc:v1:levels:index` | Array of `{ id, name, theme, cols, rows, modified }` for the level list |
| `cc:v1:level:<id>`   | One level as a **share code** — already compressed, never raw JSON     |
| `cc:v1:progress`     | `{ campaign: { <levelId>: { done, bestCoins, bestTimeMs } } }`         |
| `cc:v1:settings`     | `{ music, sfx, controls, crispScale }`                                 |
| `cc:v1:maker:last`   | `{ levelId, camX, camY, zoom, tool }` for resuming the maker           |

Levels are stored compressed so the ~5 MB quota holds hundreds of them. Quota
exhaustion surfaces as a user-visible message, never a silent failure.

**Share codes** are `base64url(deflate-raw(JSON))` using `CompressionStream`, with an
uncompressed-base64 fallback when it is unavailable. A one-character prefix marks
which encoding was used, so decoding never has to guess.

## Asset Pipeline

The Treasure Hunters pack is 1204 loose PNGs in paths containing spaces and mixed
case. Shipping them as-is means hundreds of requests and fragile filename sorting.

- **Input**: `reference/treasure-hunters/**/Sprites/**` for art and
  `reference/super-pirate-world/audio/*` for sound. Both read-only.
- **Script**: `tools/build-assets.mjs`, driven by the declarative clip list in
  `tools/asset-manifest.mjs`. Run with `npm run assets`.
- **Output**:
  - `public/assets/sprites/<clip>.png` — one horizontal strip per animation clip
  - `public/assets/tiles/<theme>.png` — tilesheets copied as-is
  - `public/assets/ui/<part>.png` — nine-slice composites: boards and papers from
    16 × 32 px tiles into 128 × 128, buttons from 16 × 14 px tiles into 56 × 56
  - `public/assets/audio/*` — copied CC0 audio
  - `src/data/atlas.json` — the manifest the runtime reads
- **Manifest entry**: `{"player/idle": {"src":"sprites/player-idle.png","fw":64,"fh":40,"n":5,"fps":10}}`
- Generated output is committed so `npm run dev` works without running the asset
  build. Regeneration must be deterministic — same inputs, byte-identical outputs.
- Animation playback defaults to **10 FPS**, the rate the pack is authored at.

### Asset coverage report

The manifest is declarative and deliberately partial: v1 packs only the clips v1
uses, and the rest of the pack stays on disk for later releases. To keep
[Goal 6](1-project-overview.md#goals) — every asset eventually finding a place in the
game — measurable rather than aspirational, `npm run assets` ends by printing a
coverage report:

```
assets: 341 / 1195 source files packed (28.5%)
  unused: Captain Clown Nose/.../15-Attack 1  (3 frames)
          Merchant Ship/Sprites/Chest/Padlock (1 frame)
          ... 612 more — see coverage.json
```

- The script walks the pack, subtracts every file the manifest references, and writes
  the remainder to `tools/coverage.json`.
- The denominator is **1195**: the 1204 PNGs under `*/Sprites/**` minus the nine
  `* (guide).png` reference images in the UI kit, which show how the nine-slice tiles
  assemble and are documentation, not game art. The 21 `.aseprite` source files are
  outside `Sprites/` and never counted.
- That exclusion list lives in the manifest and must be justified per entry — it is
  the only legitimate way for a file to leave the denominator.
- The report is informational. It never fails the build, and coverage is never a
  reason to pack an asset the game does not yet use.

## Scene and Mode Model

`App` owns the canvas, the loop, input, audio, the atlas, storage and the transition
overlay. It runs exactly one scene at a time.

```
Boot → Title → LevelSelect → Play → (results) → LevelSelect
              ↘ Maker ⇄ Play(returnTo: maker)
```

A scene implements `enter(params)`, `exit()`, `update(dt)`, `render(ctx, camera)`,
`mountUI(root)` and `unmountUI()`. Mode switching goes through the expanding-circle
transition ported from `reference/pirate-maker/28_finish/main.py:105`; the maker stashes
camera, zoom and selected tool in `enter` params so the round trip is lossless.

## Invariants

Rules the codebase must never violate. A violation is a bug even if the screen looks
correct.

1. **Simulation runs on a fixed 1/60 s timestep.** No gameplay logic reads
   wall-clock time or a raw `requestAnimationFrame` delta.
2. **Play mode and Maker mode consume the same schema through the same loader.**
   Campaign levels are exported maker levels. If the maker can produce it, play must
   load it, and vice versa.
3. **`update()` never touches the canvas or the DOM. `render()` never mutates game
   state.** No exceptions for "just this one flag".
4. **All placement and collision geometry is grid-aligned at `TILE = 32`.** No
   free-floating pixel offsets, no slopes, no non-square collision.
5. **No module hardcodes a list of entity kinds.** Anything kind-driven — palette,
   spawner, validator, preview — reads `src/data/palette.js`.
6. **Gameplay code never touches `localStorage`.** Only `src/storage/`, and only
   through `safe-storage.js`.
7. **Every maker edit goes through the command stack.** UI code never mutates
   `LevelModel` directly, or undo silently breaks.
8. **Input is read only through `core/input.js`.** No `addEventListener` in scene,
   game or maker code.
9. **The canvas draws the world only.** All UI is DOM.
10. **No code assumes a fixed viewport width.** Anything anchored to the screen
    anchors to an edge or a centre, never to a hardcoded coordinate.
11. **`core/` never imports from `game/`, `maker/`, `level/`, `data/` or `ui/`.**
    Dependencies point inward.
12. **Everything under `reference/` is read-only.** It is never modified, and nothing
    in `src/` imports from it at runtime — only `tools/` reads it, at build time.
