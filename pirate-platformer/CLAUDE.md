# Coral Corsairs

A vanilla JavaScript + Vite pirate platformer with two modes: a campaign to play,
and a Mario-Maker-style level editor that works with mouse and touch on desktop,
tablet and phone. Both modes share one engine and one level format.

## Application Building Context

Read the following files in order before implementing or making any architectural
decision:

1. `context/1-project-overview.md` — product definition, goals, features, and scope
2. `context/2-architecture.md` — system structure, boundaries, level schema,
   storage model, and invariants
3. `context/3-ui-context.md` — theme, colour tokens, typography, and component
   conventions
4. `context/4-code-standards.md` — implementation rules and conventions
5. `context/5-ai-workflow-rules.md` — development workflow, scoping rules, and
   delivery approach
6. `context/6-progress-tracker.md` — current phase, completed work, open questions,
   and next steps
7. `context/7-current-issues.md` — open defects, the fix scope rules, and the
   known-risk watchlist

Then read `context/specs/00-build-plan.md` for the unit order, and the spec for the
unit being built at `context/specs/NN-<name>.md`.

## Standing rules

- Work on **one unit at a time**, against its spec. Do not work out of order and do
  not build for a future unit.
- Everything under `reference/` is **read-only source material** — the art pack and
  the two Python projects this game is derived from. Never edit it, and never import
  from it at runtime.
- `public/assets/` and `src/data/atlas.json` are generated by `npm run assets`.
  Never hand-edit them.
- Update `context/6-progress-tracker.md` after each meaningful implementation
  change.
- Log anything found but not fixed in `context/7-current-issues.md` rather than
  fixing it inside an unrelated unit.
- If implementation changes the architecture, scope, or standards documented in the
  context files, update the relevant file **before** continuing.
- If a requirement contradicts an invariant in `context/2-architecture.md`, stop and
  report the conflict. Do not weaken an invariant to make a feature fit.
