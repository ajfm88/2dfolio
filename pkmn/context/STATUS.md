### Slice notes (for whoever claims them)

- **R1a–c** — done; see *Completed*, `notes/r1a-graphics-export.md`, and
  ARCHITECTURE → *Data flow* / *Game loop & background tabs*.
- **Driving the game from browser automation:** synthetic key taps shorter than
  one tick (20 ms at 50 fps) are lost, because `input.ts` polls key *state* once
  per tick. Hold each key ~100 ms (keydown → wait → keyup via
  `window.dispatchEvent`, `e.key` names: `z` = A, `x` = B, `Enter` = Start, arrows).
  Walking one step = ~160 ms held. More from V1b:
  - Start a temporary server with `npx vite --host 127.0.0.1 --port <spare>
    --strictPort`. Plain `npx vite` binds `localhost`, which is IPv6 `::1` here, so
    `127.0.0.1` URLs time out.
  - The splash needs a real click, then about a second before the title shows.
  - Debug overlay: backtick, then Skip Intro (Pikachu), then the warp dropdown + Warp.
  - The debug panel shows `Map … step x,y … dir:`, which is handy to read back with
    JS.
  - The first step after any warp skips the warp check (`justWarped`). A debug warp
    next to a door needs one step away and back.
  - A text box with `cont` lines needs one A press per scroll.
- **V1.** Everything is in `notes/v1-plan.md`: measured map data, the trainer table,
  the ASM-vs-upstream trainer flow, the Yellow old-man sequence, and the per-slice
  scope and verify steps. Read it instead of re-probing. **V1a and V1b are done**
  (V1b's detail: `notes/v1b-plan.md`). **V1c** (trainer battles) starts from §2.4 and
  §3 V1c. The trainer data is in the map JSON already (`trainerClass`,
  `trainerParty`, `endBattleText`, `afterBattleText`; `dialogue` = the before-battle
  text), and the Forest trainers can be reached with the debug warps. The flow to
  replace sits in `overworld_controller.ts` `handleInteraction`, `main.ts`
  `startTrainerBattle` and the `trainer_approach` state, and `battle.ts`
  `handleTrainerVictory`. Three traps:
  - The demo gate is **three** sites (search `VIRIDIAN_OLDMAN_DEMO` and "as far as
    the demo"): `overworld_controller.ts`, `story_state.ts`, and
    `extractors/game_text.ts`, which invents the text.
  - The NPC-text fallback returns wrong text for `text_asm` handlers (CONVENTIONS →
    *Map expansion workflow*).
  - Never emit a connection to an unextracted map: `performMapConnection` doesn't
    catch the failure, so the game hangs.
