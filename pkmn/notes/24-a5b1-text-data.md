## 2. `text_programs.json`

```ts
interface TextProgramsFile {
  programs: Record<string, TextOp[]>;           // pret label → commands
  textPointers: Record<string, MapTextCall[]>;  // pret TextPointers label → text ID order
}
```

**Programs.** Each `text` op is one TX_START string in A5a's encoding (`\n`, `\f`, `<LINE>`,
`<CONT>`, `<NEXT>`, `<SCROLL>`, trailing `<DONE>`/`<PROMPT>`). A string with neither ending
continues its program, as `@` does. A `<DONE>`/`<PROMPT>` string, `text_end` and `text_asm` end
their program level. `far` names its child program. RAM operands are named inputs:
`stringBuffer`, `nameBuffer`, `boxNumString`, `money`, `coins`, `hpDifference`. An unknown opcode, RAM operand
or FAR target fails extraction.

The row state for `\n` versus `<LINE>`/`<CONT>`/`<NEXT>` carries across `far` calls. A child
reached from two callers on different rows fails extraction. None does.

**Call table.** For every map text ID, the call contract that `DisplayTextID`
(`home/text_script.asm`) runs:

| `call` | Meaning | Count |
|---|---|---|
| `script` | First byte is a `TX_SCRIPT_*`; `DisplayTextID` jumps to the routine (nurse, Mart, cable club) | 3 |
| `text` | `PrintText_NoCreatingTextBox` runs `program` (a trailing `asm` op continues in code) | 45 |
| `printText` | `text_asm` whose only work is one inner `PrintText` of `program`. Three forms: inline `ld hl / call PrintText / jp TextScriptEnd`; Yellow's `farcall <Map>Print<Name>Text`, whose target is exactly `ld hl, P / call PrintText / ret`; and Viridian Forest's `ld hl, F / jp ViridianForestSign_Common` | 35 |
| `handler` | Any other `text_asm`: hand-ported TypeScript | 37 |

The walker reads only `ld b`, `ld hl`, `jr`, same-bank `jp`, `call Bankswitch`, `call PrintText`
and `jp TextScriptEnd`. Any other instruction makes the entry a `handler`, so nothing is guessed.
The test reproduces each entry from pret's statements: it follows the labels, falls through to
the next label as the code does, and resolves `farcall`/`callfar`.

Gen 1 bug kept in the data: Viridian Forest's leaving sign (text 16) prints
`ViridianForestPrintTrainerTips1Text.text`, the same program as text 11.

The table is keyed by pret's table label, not by the map, because OaksLab and ViridianMart switch
`wCurMapTextPtr` to a second table: OaksLab after a story event, ViridianMart once Oak has the
parcel. `ViridianMart_TextPointers` has 5 entries; the parcel texts 4 and 5 exist only there. The
counts are read from the ASM, not from `rom_offsets.ts` `MAP_TEXT_PTRS`. Those counts serve the
maps extractor's dialogue lookup and give ViridianMart 2.

## 3. Departures from the plan's wording (for review)

1. **Programs inline their strings instead of referencing `game_text.json` keys** (§4.1, "New
   program entries reference the canonical keys"). Each `text` op holds the string the ROM
   holds. So the canonical full blocks (choose-mon, parcel, notebook, the PCs, save, Mart,
   blackboard, Oak's speech) exist as programs with their native terminators. Nothing is
   split and no artificial key was invented. `game_text.json` gains no canonical full-block
   keys. Its split keys stay as aliases until their callers move (§4).
2. **The wrapper call table lives in `text_programs.json`** (`textPointers`), so DECISIONS #45's
   two new JSON files stay two.
3. **Ten menu texts were added beyond the first audit,** found while writing the inventory:
   - the Mart greeting (`home/text_script.asm`);
   - the four party menu messages, without the TM one (A2);
   - the item texts: not the time, no effect, threw away, OK to toss, too important to toss;
   - the home-bank `MartSignText` and `PokeCenterSignText`, with their FAR children.
   Each is read from the sym file and checked op for op against the ASM like the rest.
4. **Review fix (`notes/25-a5b1-review.md` R-1):** the eight medicine results of
   `PartyMenuItemUseMessagePointers` (Potion, Antidote, Parlyz Heal, Burn Heal, Ice Heal,
   Awakening, Full Heal, Revive) and their FAR children, with `wHPBarHPDifference` bound as
   `hpDifference` for Potion's number. `RareCandyText` waits for its item. A test reads the
   pointer table from the ASM, so a missing entry now fails. The cry op's comment now says
   PlayCry waits for the cry (N-1).
